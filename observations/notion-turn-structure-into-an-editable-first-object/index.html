Notion: Turn structure into an editable first object

A blank workspace asks people to invent both the content and its structure. Notion's database demo makes that structure concrete as a table, rows and properties. This is a product-help walkthrough, not evidence about actual new-user completion.

Visible official help demo sequence: database menu with Table, empty database with Name/Add property/New page, property-type selection including Status, then data-entry/status editing. These extracted frames support a narrow database-creation workflow, not a full new-user first-run journey. Data import, first-run placement and views/filters are not recorded.

A table gives the user a first editable object rather than a purely abstract explanation of databases.

Name, Add property and New page expose separate schema and content actions. Inference: direct manipulation may help people learn what a database contains.

A status property demonstrates typed information rather than treating every cell as plain text. Views and filters exist in documentation, but are not demonstrated by these selected frames.

Hypothesized risks and unobserved states: Flexibility increases the chance of building the wrong structure or confusing a row with a page. Property-type changes, accidental deletion, undo, sharing permissions and an empty filtered view remain unaudited. The visible Private label does not prove every sharing route or permission boundary.

What to measure
  1. 01Ask users to create three records, a status property and a useful view, then explain row/page and property/view differences.
  2. 02Measure task success and time to first useful artifact.
  3. 03Guard against data loss and unintended sharing; database creation counts alone can reward empty objects.
Job to be done

Assumed scenario; no independent user research. Workspace author building a small task tracker, wanting records and status without learning an abstract data model; workaround: a plain checklist. Hypothesized blank-workspace cost.

Alternative considered

Starter template with three example rows and reversible property edits. Blank structure wins only if it avoids template assumptions while still producing a useful first artifact. That proposed guided start addresses the assumed first-use job, which the help-demo sequence does not establish.

What would reverse this

Decision would shift toward the alternative if: A checklist or template yields equal task value faster, or users confuse schema and content and lose data.

Test scope

Exploratory protocol: recruit people who have the stated job, randomize prototype order against the alternative, and measure successful tasks out of eligible attempts in one session. Follow-up recall, attendance, payment reconciliation or delivery outcomes require a separate real-use study. No sample size, target lift or causal result is claimed.

Teach structure through a useful object, while distinguishing schema changes from content edits.
