ChatGPT teardown: you can't see what it knows about you

One-line take: ChatGPT got smarter at using context (memory, projects, custom instructions) faster than it got better at showing which context shaped an answer. That gap is the biggest improvement opportunity in the product today.

Basis: my own daily use as a heavy user. No usage data, no insider information. Claims about behavior are observations, not measurements.

Why this product

I use ChatGPT daily for research, drafting and critique, including a dedicated project for PM thinking. Heavy daily use is exactly where context features either pay off or quietly hurt.

Who the user is

A repeat, high-intent user who has already invested effort: set custom instructions, uses projects, has accumulated memory. They are not asking "is it smart enough". They are asking "will it use what I told it, and the right parts of it".

The job to be done

"Give me an answer that reflects my situation, without me re-explaining it every time, and let me trust that it did."

What works well

  • Low-friction start. One input box, no setup. Time to first value is seconds.
  • Layers of context. Custom instructions (global), projects (scoped), memory (accumulated) let users choose how much to invest.
  • Conversation as the unit. Easy to branch, regenerate, refine.

Where it breaks: invisible context

  1. No answer-level provenance. When a reply is oddly personalised, or oddly generic, the user can't tell whether memory, project files, or instructions were used.
  2. Memory is hard to audit and edit in the flow. Managing it happens in settings, away from the moment the user notices a wrong assumption.
  3. Scope bleed is a trust risk. A user can't be sure a preference from one context (work) isn't leaking into another (personal).
  4. Silent failure looks like capability failure. If a project file wasn't used, the user concludes "the model is dumb", not "the context wasn't applied". That is a retention problem disguised as a quality problem.

The improvement opportunity: "Context receipts"

A lightweight, collapsible line under an answer: "Used: 2 memories, project 'PM thinking', custom instructions". Tapping it shows exactly what was applied, with inline actions: remove for this chat, edit memory, never use for this project.

Why this, not something bigger

  • It targets trust, which gates the value of every context feature already built.
  • It is additive. Users who don't care never open it.
  • It turns a hidden system into a user-controllable one, which is also a differentiator against competitors' memory features.

How I would measure it

No invented baselines here. These are the metrics I'd instrument:

  • Primary: share of weekly active users with memory/projects enabled who keep it enabled 4 weeks later (context-feature retention).
  • Secondary: edits or removals of memory per active user (a healthy rise early means the control is being used; it should settle).
  • Quality proxy: regenerate-rate and "thumbs down" rate on answers where context was applied vs not.
  • Guardrails: median response latency, answer-page clutter (collapse rate of the receipt), and opt-out rate of memory overall (should not rise).

Risks and trade-offs

  • Extra UI on every answer adds noise. Mitigation: collapsed by default, shown only when context was actually used.
  • Exposing context makes wrong personalisation visible. That's the point, but it can reduce short-term satisfaction before it improves trust.
  • Showing exact sources for retrieved content is technically harder than for memory. Ship memory and instructions first.

What I'd test first

Show receipts only to users with 5+ memories. Compare context-feature retention and memory-disable rate against a holdout. See the A/B project for a fully worked design of this kind of test.

Takeaway

The next unlock in AI assistants is not another model jump. It's making accumulated context legible and controllable. Same lesson I apply to agent products at Niti AI: users trust what they can inspect.
