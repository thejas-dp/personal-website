Feature proposal: LinkedIn application status you can act on

Written from first-hand experience running an active PM job search. The pain is real and personal. Any numbers a reader would want (response rates, volumes) are deliberately left as "to be measured" rather than guessed.

The user problem

Applying is cheap. Hearing back is not. A candidate who applies through Easy Apply often gets no signal at all: no view confirmation they can trust, no "position closed", no hint whether to wait, follow up, or move on. The result is wasted follow-up effort, bad prioritisation of time, and a feeling that the system is a black hole.

Who suffers most: active job seekers applying to many roles at once, and mid-career people who can't afford a slow search. Who else loses: recruiters get low-quality follow-up pings and "any update?" messages because candidates have nothing else to go on.

Target audience

Primary: active seekers (applying to 10+ roles in a month). Secondary: recruiters and hiring teams posting through LinkedIn, who gain if status updates reduce inbound chasing.

Insight

Candidates don't need good news. They need a decision-useful state. "Closed" is a useful answer. Silence is not.

The solution: Application Pulse

For every application made on LinkedIn, show a single honest status with a timestamp:

  1. Submitted (always known)
  2. Seen by recruiter (only if the recruiter actually opened it)
  3. In review (recruiter moved it to a stage in their pipeline)
  4. Role closed (posting removed or marked filled, auto-detected)
  5. Not moving forward (recruiter-set, one click, optional reason from a short list)

Plus two nudges for the candidate:

  • Stale prompt after a defined waiting period: "No activity for X days. Message the recruiter, or move on?" with a pre-filled, polite follow-up.
  • Search-wide view: a tracker of all applications with states, so a candidate can see where to focus.

For recruiters: a one-click bulk "not moving forward" with a canned reason. This makes the honest state cheap to produce, which is the real constraint.

Why it might fail, and how the design answers it

Risk Design answer
Recruiters won't update statuses Bulk action, defaults from ATS integrations where available, and "role closed" auto-detected without recruiter effort
Candidates get demoralised by "not moving forward" Optional reason list and a "similar roles" prompt right there
Recruiter backlash on transparency Statuses are coarse, no mandatory feedback, no names of other candidates

Success metrics

Targets to be calibrated against baseline, not asserted here.

  • North star: share of applications that reach a terminal state (moved forward, closed, or not moving forward) within a fixed window.
  • Candidate side: reduction in repeat "any update?" messages per application; return visits to the tracker; applications per active seeker (should not fall; it should become more focused).
  • Recruiter side: share of recruiters using bulk status actions; time spent on inbound candidate messages.
  • Guardrails: application volume per posting, recruiter posting volume, recruiter churn, complaint reports.

MVP and rollout

  • V0: candidate-side tracker with only Submitted, Role closed, Stale prompt. Requires no recruiter behavior change. Tests whether candidates value even partial clarity.
  • V1: add recruiter bulk statuses for paid recruiter accounts. Measure adoption.
  • V2: ATS sync for automatic status.

What I would do first

Launch V0 to a small slice of Easy Apply users. If tracker return rate and follow-up quality improve without hurting application volume, build V1.

Takeaway

This is a two-sided honesty problem. The product wins by making the honest answer the cheapest one for the side that holds the information.
