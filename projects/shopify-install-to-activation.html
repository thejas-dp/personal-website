Growth experiment

Growth experiment: from Shopify install to first live AI agent

Experiment design. Funnel stage names reflect how a Shopify-app AI product typically works. Rates are intentionally left as "pull from analytics". No figures are claimed.

The weak funnel point

For an app installed from the Shopify App Store, the cliff is usually between install and first value. A merchant installs, sees a blank or setup-heavy state, and leaves before an agent does anything useful. Installs look healthy; activated merchants don't.

Funnel:

  1. App Store view
  2. Install
  3. Store data connected
  4. First agent configured
  5. First agent action approved or live (activation)
  6. Repeat use in week 2
  7. Paid

The step I'd attack is 3 to 5: connecting data and getting one agent live. That's where users face the most effort before seeing any benefit.

Diagnosis before design

Before running anything, answer from data and 5 merchant calls:

  • Where do users stop: before connecting data, during configuration, or at the approval step?
  • Do merchants who activate in the first session differ (store size, vertical, role of installer)?
  • What does time-to-first-action look like by cohort?

Hypothesis

If a new merchant is offered a single pre-built recommended first agent with a preview of what it would do on their own store data (a "dry run" before going live), then the share reaching first live action within 7 days rises, because seeing a concrete, store-specific outcome reduces both effort and perceived risk.

Experiment design

  • Control: current onboarding.
  • Treatment: after connecting data, the merchant lands on one recommended agent (chosen by simple rules from store category and available data), with a preview of the first 3 to 5 proposed actions on their real data and one click to approve.
  • Randomise by: shop at install, 50/50.
  • Eligibility: new installs only, excluding agency-managed or test stores.

Metrics

  • Primary: % of installs reaching first live agent action within 7 days.
  • Secondary: time from install to first action; % connecting data; week 2 return; paid conversion within the trial window.
  • Guardrails: error or rollback rate on first actions (a bad first action is worse than none), support tickets per install, uninstall within 14 days, merchant-reported trust in the agent's actions (short survey).

Why the dry run matters

For AI agents acting on a merchant's customers, the barrier isn't effort alone, it's trust. Previewing actions turns "let a black box email my customers" into "approve these five things I can read". That reasoning comes from working on agent products where approval and control are central.

Risks

  • Recommended agent might be wrong for the store. Mitigation: simple rules, easy switch, and track mismatch.
  • Preview adds compute cost and latency. Track time to preview.
  • Faster activation of low-fit merchants may raise early churn. The 14-day uninstall guardrail catches it.

Decision rule

Ship if primary rises meaningfully, guardrails hold, and week 2 return does not fall. If activation rises but week 2 return falls, the dry run is getting merchants live on the wrong agent, so tune recommendation rules.

Follow-up experiments

  1. Email and in-app nudge at 24 hours for installs that connected data but didn't go live.
  2. Concierge setup call offered to larger stores, as a high-touch arm.
  3. Case-study proof on the install page for relevant verticals.

Takeaway

In AI products, activation is a trust problem before it's a UX problem. Design the first minutes so the user sees the result and keeps control.
